# Грабли и неочевидные правила

Список вещей, на которых легко обжечься. Прочитать **до первого PR** — большинство из них
не видны из кода, но ломают сборку, релиз или работу у пользователя.

## Сборка

### Перед каждой сборкой Windows — `sync_windows_plugins.ps1`
Firebase — Android-only. В сгенерированном списке Windows-плагинов он быть не должен, иначе
линковка падает. Запускать после каждого `flutter pub get`:
```powershell
powershell -File tool/sync_windows_plugins.ps1
```

### Linux нельзя собрать Windows-SDK
Linux-таргет собирается **только** на нативном Linux или в WSL (`tool/build_linux_wsl.sh`).
Кросс-сборка из Windows не работает.

### Нативные ядра — НЕ Flutter-ассеты
`assets/bin/windows` и `assets/bin/linux` намеренно **не** объявлены ассетами в `pubspec.yaml`
(объявлены только geo-базы). Flutter пакует ассеты во все платформы, и десктоп-бинарники +
geo тянулись в Android APK (~150 МБ мусора). Ядра раскладываются рядом с exe через
`windows/`/`linux/` CMakeLists, Android берёт их из `jniLibs`. **Не переноси бинарники в
`flutter: assets:` ради удобства** — раздуешь APK.

## Кодировки на Windows (PowerShell)

**Самая коварная грабля.** Non-ASCII символы (em-dash `—`, кириллица, «умные кавычки») в
`.ps1`-скриптах и в файлах, которые они генерируют, ломают сборку и **встроенный апдейтер**:
консоль Windows читает их как cp1251, а не UTF-8, и хеши/пути бьются.

- В `.ps1` и генерируемых файлах держи **чистый ASCII**.
- Файлы хешей (`.sha256`) — **ASCII без BOM**.
- Многострочные строки в PowerShell — через here-string `@'...'@` (закрывающий `'@` строго в
  начале строки, без отступа).

## Релизы

### Каждый ассет обязан нести `.sha256` (fail-closed)
`UpdateService` проверяет SHA-256 скачанного файла и **отказывается ставить** обновление,
если sidecar-файла хеша нет или он не совпал. Это защита целостности.
- Релизь через `tool/make_release.ps1` — он генерирует `.sha256` сам (ASCII без BOM).
- При **ручной** заливке релиза не забудь приложить `<имя_ассета>.sha256` к **каждому** ассету,
  иначе пользователи не смогут обновиться.

### Версия и тег — из `pubspec.yaml`
Тег релиза (`vX.Y.Z`) берётся из `version:`. Поднял версию в `pubspec.yaml` — это и есть
источник истины для релиза. Апдейтер сравнивает версии **и даты публикации** релизов.

### GitHub API требует `User-Agent`
Запросы к `api.github.com` без заголовка `User-Agent` отвечают **403**. У неавторизованного
доступа лимит 60 запросов/час на IP — при активном VPN это общий лимит exit-узла, так что
проверку обновлений лучше делать без VPN.

## Windows-ядра и Defender

`xray.exe` / `wireproxy.exe` под Windows:
- собирать **unstripped** (стрипнутый бинарь Defender чаще ловит как угрозу);
- бандлить в ассеты и запускать **из папки приложения**, а **не из `%TEMP%`** — запуск
  неизвестного exe из временной папки триггерит эвристики Defender.

## UI: трей переиспользует то же окно

Меню в трее (`tray_menu_screen.dart`) — это **то же самое окно приложения**, суженное до
~288px, а не отдельное окно.
- Overflow вкладок/контента нужно гасить по **порогу ширины окна**, иначе в узком трее-режиме
  всё ломается.
- Флаг «показываем трей-меню» снимай **синхронно до `await`** — иначе словишь обращение к
  ref/виджету после unmount и кнопки перестанут работать.

## Поведение, которое легко принять за баг

- **Android всегда TUN.** На десктопе есть выбор Proxy/TUN, на Android — нет (только
  `VpnService`/TUN). `ConnectionMode.fromStorage` по умолчанию возвращает `tun`.
- **Split tunneling в Proxy-режиме на Windows ≠ Android per-app.** Per-process split работает
  только в TUN. В Proxy он просто игнорируется (в лог пишется предупреждение).
- **Фон на десктопе ≠ фон на Android.** На Windows/Linux подписки обновляются по таймеру, пока
  приложение открыто (свёрнутое в трей — считается открытым). Полностью закрытое десктоп-
  приложение фоном не обновляется. На Android — WorkManager обновляет даже после убийства.
- **Обновления через прокси идут по HTTP-порту, не SOCKS.** Dart `HttpClient` не умеет SOCKS,
  поэтому при активном VPN на десктопе апдейт-трафик заворачивается в локальный **HTTP**-прокси
  (`PROXY host:httpPort`), а строка вида `SOCKS5 ...` в `findProxy` уронит запрос с
  `HttpException: Invalid proxy configuration`.
- **GeoIP в xray — это поле `ip`.** Правило `{"geoip": [...]}` xray молча игнорирует и падает
  с `app/router: this rule has no effective fields`. Правильно: `{"ip": ["geoip:ru"], ...}`.

## Данные и хранение

- Настройки/серверы на Windows — в `%APPDATA%\Roaming\com.keqdroid\keqdroid\`, **не** рядом с
  exe. Перенос между машинами — через экспорт/импорт в настройках.
- `StorageService` загружает списки **устойчиво к битым записям**: одна повреждённая
  запись (например, после смены схемы при апгрейде) пропускается с логом, а не уносит весь
  список. Если добавляешь поле в `ServerItem`/`Subscription`/`RoutingRule` — делай парсинг
  толерантным к его отсутствию (null-aware), чтобы старые данные не падали.

## Локализация

- Правишь строку — правь **все 4** ARB (`en/ru/de/zh`). База — `app_en.arb`.
- Не редактируй `app_localizations*.dart` руками — они генерируемые
  (`flutter gen-l10n` / `flutter pub get`).
