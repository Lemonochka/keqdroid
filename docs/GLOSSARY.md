# Словарь предметной области

Если ты не из мира VPN/прокси — начни отсюда. Эти термины встречаются в коде и остальных
доках на каждом шагу.

## Ядра (cores)

Внешние нативные бинарники, которые реально гоняют трафик. Приложение их только запускает и
кормит JSON-конфигом.

| Ядро | Что делает | Где |
|------|------------|-----|
| **xray** | основной прокси-движок: реализует протоколы (VLESS/VMess/Trojan/SS/Hysteria2), поднимает локальный SOCKS/HTTP, делает маршрутизацию по доменам/IP/geoip. Целевая версия — **26.x**. | все платформы |
| **sing-box** | владеет **TUN-устройством** на десктопе: забирает весь системный трафик и отдаёт его аплинку (локальному SOCKS от xray). | Windows/Linux TUN |
| **wireproxy** (`wireproxy-awg`) | реализует **AmneziaWG** и отдаёт его как локальный SOCKS/HTTP (proxy-режим без админ-прав). | Windows/Linux |
| **keqrnel** | **единый бинарь = xray + sing-box** в одном процессе. Меньше RAM и размер. Включается настройкой `coreEngine: keqrnel`. | Windows/Linux |
| **tun2socks** | на Android превращает TUN-трафик в SOCKS-запросы к xray. | Android (внутри VpnService) |
| **geoip.dat / geosite.dat** | базы для правил `geoip:` / `geosite:` (страны/категории доменов). | рядом с ядром |

## Режимы и пути трафика

- **Proxy-режим** — приложение поднимает локальный SOCKS/HTTP (например, `127.0.0.1:2080`).
  На Windows дополнительно прописывается **системный прокси**, чтобы браузеры пошли через него.
  Не нужны админ-права. Минус: не весь софт уважает системный прокси.
- **TUN-режим** — создаётся виртуальный сетевой адаптер (TUN), и **весь** трафик ОС идёт в
  туннель. Нужны админ-права (Windows) / root через `pkexec` (Linux). На Android аналог — это
  `VpnService`, и там режим **всегда TUN**.
- **`ConnectionMode`** (enum) — `proxy` | `tun`.
- **`VpnBackend`** (enum) — `xray` | `awg` (AmneziaWG идёт мимо xray-пайплайна).
- **`coreEngine`** — `chain` (xray→sing-box, два процесса) | `keqrnel` (единый процесс).

## Протоколы

Способы «обёртки» трафика, чтобы он выглядел безобидно и проходил фильтрацию.

| Протокол | Ссылка | Заметки |
|----------|--------|---------|
| **VLESS** | `vless://` | лёгкий, часто с XTLS/Reality |
| **VMess** | `vmess://` | конфиг — base64(JSON) внутри ссылки |
| **Trojan** | `trojan://` | маскируется под обычный HTTPS |
| **Shadowsocks** | `ss://` | классика; SIP002 base64 |
| **Hysteria 2** | `hysteria2://`, `hy2://` | QUIC/UDP, быстрый; **v1 не поддерживается** |
| **AmneziaWG** | файл `.conf` | обфусцированный WireGuard (версии 1.0/1.5/2.0); добавляется файлом/текстом, не ссылкой |

- **Reality / XTLS** — современная TLS-маскировка для VLESS (поля `pbk`/`sid`/`spx`,
  fingerprint).
- **ALPN, SNI, fingerprint (fp), ECH** — параметры TLS-рукопожатия, влияют на незаметность.

## Подписки и серверы

- **Подписка (subscription)** — URL, по которому провайдер отдаёт **список серверов**
  (часто base64 со ссылками). Приложение периодически их обновляет.
- **Сервер (`ServerItem`)** — одна конфигурация подключения (raw-ссылка + метаданные:
  пинг, страна, избранное). Бывает из подписки или добавлен вручную.
- **`X-Subscription-Userinfo`** — HTTP-заголовок ответа подписки с лимитами трафика и датой
  истечения (показываются в UI).
- **HWID** — идентификатор устройства, который некоторые провайдеры требуют для привязки
  подписки. Отправляется заголовком/в query; включается в настройках.
- **Стабильный ключ (`_stableKey`)** — как приложение понимает, что «тот же сервер» между
  обновлениями подписки, даже если ротировались reality-параметры. Нужен для дедупа и
  сохранения пингов/избранного.

## Маршрутизация (routing)

Решение «куда пустить конкретный трафик»: напрямую, через прокси или в блок.

- **direct** — мимо туннеля, напрямую (например, локальные адреса, отечественные сайты).
- **proxy** — через сервер/туннель.
- **block** — заблокировать (реклама, телеметрия).
- **Списки правил** — смешанные: домены (`example.com`, `domain:`, `full:`, `regexp:`,
  `geosite:`), IP/CIDR (`1.2.3.4/24`) и `geoip:<код страны>`.
- **geoip / geosite** — правила по стране IP / категории домена из `geoip.dat`/`geosite.dat`.
  В **xray** geoip задаётся внутри поля `ip` (`ip: ["geoip:ru"]`), отдельного поля `geoip`
  нет — частый источник ошибки «this rule has no effective fields».
- **Пресеты** (`routing_presets.dart`) — готовые списки direct/proxy/block.

## Split tunneling (раздельное туннелирование)

Какие приложения/программы пускать в туннель, а какие мимо.

- **Android** — по **пакетам** приложений (`includePackages`/`excludePackages`).
- **Windows** — по **именам процессов**, и только в **TUN-режиме** (в Proxy так не выйдет).
- **`AppRoutingMode`** (enum):
  - `allProxy` — всё в прокси;
  - `onlySelected` — в прокси только выбранные;
  - `allExceptSelected` — в прокси всё, кроме выбранных.

## Прочее

- **Kill switch** — если туннель упал, не выпускать трафик напрямую (правила `0.0.0.0/1` +
  `128.0.0.0/1` ловят весь трафик в обход default route и гонят в `proxy`).
- **LAN Proxy / LAN sharing** — отдать локальный прокси в локальную сеть (другие устройства
  могут им пользоваться).
- **Пинг**: **TCP** (открыть соединение), **ICMP** (классический ping), **URL** (HTTP-запрос
  через прокси → реальная задержка), **speed** (скачать фикс-payload → kbps).
- **Системный прокси (Windows)** — настройка ОС, через которую Chromium-браузеры идут в
  локальный прокси. Firefox её игнорирует — для него есть `firefox_proxy_helper` (правит
  `user.js`).
- **MethodChannel / EventChannel** — мост Flutter↔натив. У этого приложения канал —
  `keqdis_vpn_channel` (методы — команды нативу, события — поток статуса/статистики).
- **WorkManager** — Android-механизм фоновых задач (обновление подписок, когда приложение
  убито).
- **wintun.dll** — драйвер TUN-адаптера для Windows (нужен sing-box в TUN-режиме).
- **pkexec / polkit** — механизм запроса прав root в Linux (для TUN).
