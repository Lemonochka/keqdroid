# Режимы и раздельное туннелирование

## VPN и Прокси

| | VPN (на ПК называется TUN) | Прокси |
|---|---|---|
| что идёт через сервер | весь трафик устройства | только программы, в которых указан прокси |
| перехват DNS | есть | нет |
| маршруты по приложениям и раздельное туннелирование | работают | не работают |
| Fake IP | работает | не работает |
| что нужно | Android: разрешение VPN. Windows: права администратора. Linux: права root | ничего |

В режиме Прокси приложение открывает SOCKS на `127.0.0.1:2080` и HTTP на `127.0.0.1:2081`. На Windows оно само прописывает системный прокси, и его подхватывают браузеры и большинство программ. На Linux прокси прописывается в настройках GNOME и KDE. В остальных случаях адрес и порт нужно указать в программе вручную.

В этом режиме у прокси нет пароля, потому что в системный прокси и в поле прокси в настройках Wi-Fi пароль не вписать. Исключение – Android: там пароль по умолчанию включён, а выключается в «О приложении» → «Пароль для локального прокси».

В режиме VPN эти порты тоже открыты, но защищены паролем, который меняется при каждом подключении. Через них работает само приложение: обновляет подписки, проверяет обновления, определяет страну для флага. Другие программы ими воспользоваться не могут.

## Раздельное туннелирование

<SplitModes />

| Режим | Через VPN идут |
|---|---|
| Все приложения | все |
| Только выбранные | только отмеченные, остальные напрямую |
| Все кроме выбранных | все, кроме отмеченных |

Работает только в режиме VPN. Список общий для всех профилей маршрутизации.

**Android.** Список применяет сама система: приложение, которое не входит в VPN, работает так, будто VPN выключен. Кнопка «Добавить российские приложения в обход» отмечает установленные приложения из встроенного списка.

**Windows и Linux.** Здесь в туннель попадает весь трафик, а ядро уже само отправляет мимо туннеля программы, которым там быть не нужно. Программу можно указать по имени (`chrome.exe`, `firefox`) или полным путём. Имя подходит для любой программы с таким именем, путь – только для этой. На Windows регистр не важен, а `.exe` приложение допишет само. В режиме «Все приложения» Tailscale, WireGuard и OpenVPN всегда идут мимо туннеля, чтобы не получилось туннеля в туннеле.

Сам keqdroid никогда не входит в VPN, иначе его соединения с сервером уходили бы в его же туннель по кругу. Его запросы идут через локальный прокси с паролем, то есть всё равно через сервер.

## Раздельное туннелирование или маршрут по приложению

- Раздельное туннелирование решает, попадает ли приложение в VPN вообще.
- Маршрут для отдельного приложения решает, куда пойдёт трафик приложения, которое уже попало в VPN: напрямую, через другой сервер или в блок.

Поэтому маршрут для приложения, которое раздельное туннелирование выводит из VPN, не действует. Приложение предупреждает об этом на карточке маршрута.

## Раздача в локальную сеть

Настройка «LAN прокси» открывает прокси для других устройств в вашей сети: SOCKS на порту 1080 и HTTP на порту 8080, при желании с логином и паролем. Так можно пустить через сервер, например, телевизор или приставку, для которых нет своего клиента.

Подключиться могут только устройства из частных сетей. Их трафик целиком идёт через сервер, ваши маршруты на него не действуют.
